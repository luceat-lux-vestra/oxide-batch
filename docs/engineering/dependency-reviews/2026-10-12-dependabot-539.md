# Tokio and trybuild patch review (#539)

This review covers only the locked updates Tokio 1.53.1 → 1.53.2 and trybuild
1.0.121 → 1.0.122. Cargo requirements, features, package sources and the remaining
resolved graph are unchanged. Maintainers own subsequent upgrades and rollback
through a reviewed lockfile change and corresponding campaign closure refresh.

## Runtime architecture and dependency admission

Tokio is a critical dependency governed by accepted
[ADR-0002](../../architecture/decisions/0002-execution-model.md). The
[upstream 1.53.2 release](https://github.com/tokio-rs/tokio/releases/tag/tokio-1.53.2)
fixes blocking-pool shutdown, semaphore acquisition, timer/waker locking and
channel edge cases, alongside platform-specific I/O/process fixes. Applying
these fixes through the existing runtime is preferable to implementing private
workarounds. This patch retains the accepted async execution, bounded blocking,
cooperative cancellation and application-owned runtime boundary. It adds no
runtime API exposure, global executor or replacement abstraction.

The downloaded Tokio manifest still declares MIT licensing and Rust 1.71;
its dependency, feature and platform dependency sections are unchanged.
The package is resolved from crates.io with checksum
`e95f91fcc7a621e8b030f6aa23c71fe9838ae2fb4d8118b75602a328f5144044`.
The official release tag resolves to
`ff0c4068a4ba5f3af0fe3c5657ba42879b6ea599`.

Trybuild is confined to development-time compiler contract checks. The
[upstream 1.0.122 release](https://github.com/dtolnay/trybuild/releases/tag/1.0.122)
adjusts generated workspace handling of unused-dependency warnings. Its downloaded
manifest declares MIT OR Apache-2.0 and Rust 1.88, below the workspace MSRV 1.95.

## Evidence and impact

All eleven campaign dependency closures change exactly these two version/checksum
records. Their root declarations, package inventory and all other identities
are preserved. The generator is host-sensitive: a macOS invocation includes
different native-certificate packages from the Linux campaign environment.
Consequently the reviewed update preserves the committed Linux baseline;
the exact-HEAD Linux Evidence authority must independently recompute and accept
all eleven closures before merge.

Local validation completed:

- `cargo +1.95.0 check --workspace --all-targets --all-features --locked`;
- `cargo test -p oxide-batch --all-features --locked --test repeat_runtime
  --test local_split_runtime --test local_partition_runtime --test ui`:
  42 runtime tests and all seven compile-fail fixtures;
- `cargo test -p oxide-batch --all-features --locked --lib shutdown::tests`;
- `cargo deny --locked check`: advisories, licenses, bans and sources pass;
- `cargo xtask evidence`: 21 retained reports preserve their recorded bytes and
  internally valid provenance.

These local checks do not replace required exact-HEAD GitHub CI. They do not
prove Linux, Windows or PostgreSQL behavior by themselves. The retained reports
remain historical: changed reachable dependency identities invalidate current
semantic freshness, and this PR does not rewrite or promote those reports.
Ordinary dependency updates are `stale-only` under the accepted campaign routing;
fresh report promotion belongs to subsequent deep/scheduled/release validation.

No Spring capability, public contract, durable schema, migration, checkpoint,
transaction, delivery, telemetry or supported-platform commitment changes.
No compatibility-ledger promotion or new release-readiness claim is made.
